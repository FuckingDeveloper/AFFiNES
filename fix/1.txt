# Часть 1. Admin Dashboard в self-hosted

## Проблема

В self-hosted AFFiNE frontend выполняет GraphQL-запрос `adminDashboard`, однако backend запрещает его через cloud-only guard.

В `AdminWorkspaceResolver` имеется логика вида:

```ts
private assertCloudOnly() {
  if (env.selfhosted) {
    throw new NotFoundException();
  }
}
```

А resolver:

```ts
async adminDashboard(...) {
  this.assertCloudOnly();

  // ...
  return this.models.workspaceAnalytics.adminGetDashboard(...);
}
```

В результате self-hosted получает GraphQL-ошибку:

```json
{
  "path": ["adminDashboard"],
  "status": 404,
  "type": "RESOURCE_NOT_FOUND"
}
```

Frontend при этом знает, что работает в self-hosted:

```ts
const shouldShowTopSharedLinks = !environment.isSelfHosted;
```

но основной запрос `adminDashboardOverviewQuery` всё равно выполняется.

После ошибки frontend не имеет нормального error-state и может привести UI к белой странице.

---

# Цель

Admin Dashboard должен нормально открываться в self-hosted.

При этом нельзя просто удалить:

```ts
this.assertCloudOnly();
```

пока не подтверждено, что `adminGetDashboard()` полностью совместим с self-hosted.

---

# Шаг 1. Исследовать `adminGetDashboard`

Найти реализацию:

```ts
workspaceAnalytics.adminGetDashboard(...)
```

и проследить все её зависимости.

Особенно проверить использование таблиц/представлений вроде:

```text
sync_active_users_minutely
workspace_admin_stats
workspace_admin_stats_daily
workspace_doc_view_daily
ai_sessions_messages
```

Для каждой используемой таблицы определить:

1. создаётся ли она миграциями self-hosted;
2. существует ли она во всех поддерживаемых конфигурациях;
3. наполняется ли она в self-hosted;
4. зависит ли её наполнение от cloud-only analytics pipeline;
5. может ли запрос падать при пустой таблице;
6. может ли запрос падать при отсутствии таблицы.

Не предполагать — проверить код, migrations/schema и collectors/jobs.

# Шаг 2. Разделить dashboard metrics по доступности

Определить показатели dashboard, которые можно получить в self-hosted из основной БД.

Например потенциально:

* количество workspaces;
* количество пользователей;
* количество документов;
* количество участников;
* storage usage;
* другие aggregate values, которые доступны без cloud analytics.

Отдельно определить показатели, которые зависят от cloud-only analytics.

Для cloud-only показателей выбрать один из двух вариантов.

### Предпочтительный вариант

Backend возвращает валидную структуру GraphQL, но значение отсутствующей аналитики становится:

```ts
0
```

или:

```ts
[]
```

или:

```ts
null
```

если GraphQL schema это допускает.

### Альтернативный вариант

Frontend скрывает конкретные карточки, которые физически невозможно рассчитать в self-hosted.

Не скрывать весь Dashboard только потому, что один metric недоступен.

# Шаг 3. Сделать `adminDashboard` self-host-compatible

После анализа переделать resolver/model так, чтобы:

```graphql
adminDashboard
```

работал в self-hosted.

Cloud-режим должен сохранить прежнее поведение.

Рекомендуемая архитектура:

```ts
if (env.selfhosted) {
  return selfHostedDashboard;
}

return cloudDashboard;
```

или equivalent разделение непосредственно в analytics model/service.

Не размазывать проверки:

```ts
if (selfhosted)
```

по десяткам frontend-компонентов, если можно централизовать различие на backend/service уровне.

# Шаг 4. Не затронуть остальные cloud-only endpoints

Если:

```ts
assertCloudOnly()
```

используется другими resolver-методами, не удалять сам guard глобально.

Нужно снять cloud-only ограничение только с того функционала, который действительно становится поддерживаемым.

Например вместо:

```ts
async adminDashboard() {
  this.assertCloudOnly();
}
```

dashboard должен иметь собственную self-host-aware реализацию.

Другие методы, которые реально предназначены только для AFFiNE Cloud, должны продолжать возвращать прежние ошибки.

# Шаг 6. Убедиться, что query не вызывается там, где он не нужен

Проверить, можно ли использовать существующий механизм условного query execution.

Если некоторые dashboard query действительно остаются cloud-only, в self-hosted они вообще не должны отправляться.

Но основной dashboard query после данной задачи желательно сделать self-host-compatible.

То есть не маскировать backend-проблему исключительно:


# Часть 2. Полноценный i18n Task Tracker

## Проблема

Task Tracker содержит пользовательский интерфейс с английскими строками, прописанными непосредственно в коде.

Примеры:

```ts
const PRIORITY_OPTIONS = [
  { value: 'urgent', label: 'Urgent' },
  { value: 'high', label: 'High' },
  { value: 'medium', label: 'Medium' },
  { value: 'low', label: 'Low' },
];
```

```ts
return 'No due date';
```

```ts
new Intl.DateTimeFormat('en-US', ...)
```

Дефолтная конфигурация также содержит:

```ts
export const DEFAULT_FLOW = [
  { id: 'todo', title: 'To Do' },
  { id: 'in-progress', title: 'In Progress' },
  { id: 'done', title: 'Done' },
];

export const DEFAULT_BOARD_TITLE = 'Main board';
```

Из-за этого переключение языка AFFiNE на русский не переводит Task Tracker.

---

# Цель

Все системные элементы Task Tracker должны использовать штатный i18n AFFiNE.

Минимум поддержать:

```text
en
ru
```

При этом пользовательские данные переводить нельзя.

* как именуются translation keys;
* как передаются interpolation variables;
* как определяется текущая locale;
* как форматируются даты;
* есть ли helper для locale-aware dates.

Использовать именно существующий механизм AFFiNE.

# Шаг 3. Перевести enum-like options правильно

Не хранить translated label в глобальной константе типа:

```ts
{
  value: 'urgent',
  label: 'Urgent'
}
```

если translation API требует runtime context.

Вместо этого оставить стабильное значение:

```ts
type Priority = 'urgent' | 'high' | 'medium' | 'low';
```

а label получать во время рендера:

```ts
getPriorityLabel(priority)
```

или через translation mapping:

```ts
const priorityLabels = {
  urgent: t['...urgent'](),
  high: t['...high'](),
  medium: t['...medium'](),
  low: t['...low'](),
};
```

Использовать стиль, принятый в AFFiNE.

То же самое сделать для:

```text
task type
priority
complexity
system status
other enum-like UI fields
```

# Шаг 4. Исправить форматирование дат

Убрать:

```ts
new Intl.DateTimeFormat('en-US', ...)
```

Текущая locale должна браться из приложения.

Использовать существующий AFFiNE helper, если он есть.

Если его нет, locale должна вычисляться через уже существующий i18n state.

Например логически:

```ts
new Intl.DateTimeFormat(currentLocale, options)
```

но конкретную реализацию взять из существующего AFFiNE кода.

Проверить:

* `en`;
* `ru`;
* даты deadline;
* short date;
* date/time;
* `No due date`.

# Шаг 6. Локализация встроенных дефолтов

Стандартные значения Task Tracker:

```text
Main board
To Do
In Progress
Done
```

должны отображаться локализованно только пока они являются системными defaults.

Для русского:

```text
Main board   -> Основная доска
To Do        -> К выполнению
In Progress  -> В работе
Done         -> Готово
```

Но нельзя делать:

```ts
t(board.title)
```

или:

```ts
if (title === 'To Do')
```

как основную модель определения дефолта.

Не привязывать identity системного объекта к display string.

Использовать стабильный ID или явный marker.

Для flow уже имеются IDs:

```ts
todo
in-progress
done
```

Значит отображение может быть основано на ID.

Логика:

```text
если stage является встроенным default и не был переименован:
    показать translation по ID
иначе:
    показать сохранённый title
```

# Важная проблема: как определить rename

Нужно исследовать текущую data model.

Если пользователь меняет:

```text
To Do
```

на:

```text
Очередь
```

система должна запомнить, что это custom title.

Нельзя после следующей смены locale снова показывать системный перевод.

Предпочтительные варианты в порядке приоритета:

### Вариант A — уже существует признак default/custom

Использовать его.

### Вариант B — model хранит stable ID + optional title override

Лучший формат:

```ts
{
  id: 'todo',
  title?: string
}
```

где отсутствие `title` означает использовать системный локализованный label.

При rename:

```ts
title = userInput
```

### Вариант C — требуется миграция

Если сейчас default titles физически сохраняются как:

```text
To Do
```

проверить, как безопасно отличить legacy default от custom data.

Не выполнять destructive migration без необходимости.

Обязательно учитывать существующие boards.
